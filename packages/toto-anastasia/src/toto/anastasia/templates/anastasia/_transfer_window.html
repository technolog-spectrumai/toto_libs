{% load i18n %} {% comment %}THE TRANSFER WINDOW — the person's Vault and this Capsule, side by side. Two panes and two arrows: tick files on either side, choose where they go on the other, press the arrow that points there. Side by side from `lg` up; stacked on a phone, Vault above and Capsule below, with the arrows turned to point down and up — `vault/copy_files.html`'s one breakpoint, for the same reason. ONE FILE PER REQUEST, ONE AFTER ANOTHER (`desk_transfer.py`), so the bar is real progress: it moves when a file is done, and each file lands a line saying what happened to it — the antivirus scan modal's shape. A refusal about one file stops nothing else; a refusal about the person (quota, funds) or the platform (a runtime that stopped answering) stops the batch, because every later file would meet it too. "Stop after this file" is always there while it runs. WHAT EACH DIRECTION COSTS is said in the footer before anything is pressed: into the Capsule is free, out of it is charged and virus-scanned exactly like an upload. The rows are the two panes' own shapes (`panes.vault_pane_rows`, `views._vault_rows`). Row ids are positional and change on refresh, so what is open, ticked and chosen is kept on real keys — bucket, folder and file primary keys on the Vault side, paths on the Capsule side — and the rows are KEYED by them too: keyed by position, a refresh made Alpine reuse one file's checkbox for another, and a charged copy out could take a file drawn unticked. Opened by an `open-transfer` window event, with `{folder}` to preselect where in the Capsule files should land. Lives inside `capsuleView()`, whose `humanBytes` it uses. {% endcomment %} {{ transfer_vault.items|json_script:"transfer-vault-rows" }}
