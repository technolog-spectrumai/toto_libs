{% load i18n app_tags %} {% comment %}Shared sub-nav for the Media section: video | ocr. Caller passes active_tab = video | ocr. Two apps, two independent flags (BUILD_VOD, BUILD_OCR), and neither implies the other — so on a real host this bar may hold two entries, one, or none. Each is therefore doubly guarded, and both guards are load-bearing: * `|app_installed` hides the tab when the app is not in INSTALLED_APPS; * the `url … as` form swallows NoReverseMatch, so an app that is installed but mounted at no URL degrades to no tab rather than a 500. It lives in toto-base rather than in vod or ocr on purpose: Django only loads template dirs for INSTALLED apps, so a partial living in, say, vod/templates/ would vanish exactly when vod is switched off — which is the case these flags create. core already knows these labels (see core.views._manual_features). It sits in oya/ rather than a templates/media/ directory of its own for a dull but expensive reason: .gitignore has a `media/` rule for MEDIA_ROOT, and it matches at any depth, so a templates/media/ partial is silently never committed. The file existed, rendered locally and shipped in no wheel until zenobia's clean-env gate caught the missing template. oya/ is where core's shared templates live anyway (base.html, _dashboard_cards.html). The ffmpeg half of this section — manta, fileservices and transcription — moved to the toto-media-ops package in 1.21, which no host pins (see that package's README). Their tabs went with them rather than being left to self-hide, so this bar states what a host can actually have. A host that does pin that wheel adds its tabs back here. Active state is decided server-side; dark/light stays Alpine (darkMode). Written as a comment tag rather than a hash-brace comment because that form is single-line only — spanning one over several lines makes Django render the whole block as visible page text.{% endcomment %}
