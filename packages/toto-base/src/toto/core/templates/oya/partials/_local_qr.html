Two sources, in order. `tailnet_public_url` wins when the stack is on a tailnet. deploy.py knows the MagicDNS name and exports it (TAILNET_PUBLIC_URL), and that is the address to hand round — `tailscale cert` issues for the NAME, so it opens without a certificate warning, which the tailnet IP does not. It has to come from the server because the browser cannot know it: whoever ran the deploy is looking at localhost. Otherwise the BROWSER's own window.location.origin, because the server routinely cannot name an address that works. Behind nginx it sees a container hostname; on a LAN it knows an interface IP but not which one is routable; through a tunnel or a port-forward it knows nothing at all. The URL in the visitor's address bar is the one that demonstrably reached this page, so it is the one worth encoding — whatever the networking turned out to be. Shown to everyone, unlike the onion/tailnet QRs beside it: this encodes the address the visitor already has, so it discloses nothing. Hidden when JS is off (Tor Browser) — those readers are exactly who the server-rendered onion QR is for. Include once, anywhere in the page body; it carries its own script. {% endcomment %}
