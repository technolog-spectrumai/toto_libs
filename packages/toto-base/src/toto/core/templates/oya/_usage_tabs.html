{% load i18n app_tags %} {% comment %}Sub-nav of the Usage super-tab: metered | how you're charged | records. Caller passes active_tab = metered | taxes | records. This strip carried NINE chips: Records, My usage, Levies, Time dials, Prices, Limits, Rate desk, Allowances, Metrics. Four of them — Limits, Rate desk, Prices, Metrics — all plausibly answered "where do I set what this costs", and the one most people meant lived in a different app from the tab that named it. They were nine screens keyed by one string, the metric code, so answering a single question meant visiting five and holding the answer in your head. They are now one destination, "Metered", where each thing carries its own limit, price, free allowance, dials and usage. Levies and Time dials are sections of the things they belong to (storage.gb_day and time.hold); the rate desk, the allowances desk and the metrics dashboard are gone as places. The three that remain are genuinely different objects: * Metered — the things, and everything about each one. * Charges — the KINDS of charge, read-only, each linking to its knob. * Records — the ledger trail: what was actually billed, and when. Guarded per entry the same way oya/_economy_tabs.html is, and for a sharper reason: placidia installs toto.quota and toto.tariffs but NOT toto.tax, so this bar genuinely renders with a hole in it on a real host. STAFF vs USER. Both roles get the same destinations now. The old split — hiding every chip that SET a number — is what forced staff and members onto different pages for the same question; each page does the disclosure itself instead, showing a member the numbers and staff the editors. Hiding was always cosmetic anyway: every view keeps its own gate, so a typed URL is still refused. "Records" stays staff-first because a member's own records are already on the thing. Active state is decided server-side; dark/light stays Alpine (darkMode).{% endcomment %}
