{% load i18n app_tags %} {% comment %}ONE strip for the whole economy — wallet, usage and everything under it. Caller passes active_tab = assets | usage | bourse | metered | records | fees. It used to be TWO strips on two lines: this file, plus oya/_usage_tabs.html included underneath it by quota/base.html, with `-mt-2` pulling the second row up under the first. They were also styled differently — pill buttons above, underline chips below — which made one navigation look like two. They are merged here, keeping the visual split as a divider rather than a line break: the left group are places, the right group are views OF one place. Before those two there were four, and two of them stacked: tariffs/base.html extended assets/base.html, so every tariffs page rendered the ten-tab assets bar AND a second chip row underneath, while quota/base.html and tax/base.html were separate roots cross-linked by {% templatetag openblock %} if HAS_TARIFFS {% templatetag closeblock %} guards. The mint had no navigation at all and was reachable only by typing its URL. Each entry is doubly guarded, and both guards are load-bearing (the oya/_media_tabs.html reasoning, which applies here with more force because the economy spans three packages): * `|app_installed` hides the tab when the app is not in INSTALLED_APPS; * the `url … as` form swallows NoReverseMatch, so an app that is installed but mounted at no URL degrades to no tab rather than a 500. It lives in toto-base/oya/ and not in toto.assets for the same two reasons _media_tabs.html records. Django loads template dirs only for INSTALLED apps, and this bar must render on placidia — which pins toto-economy but installs only assets and tariffs — and on any host that has toto.quota and nothing else. And .gitignore carries a `media/` rule that matches at any depth, so a shared partial must not live under a templates/media/ path; oya/ is where core's shared templates already live. ROLE SPLIT, and one bug fixed in the merge. Staff and users get the same tabs pointing at different places where the destinations differ in KIND rather than in permission. But "Usage" used to send staff to tariffs:usage_list — the platform's charge records — which meant a staff member could not reach their own usage bars from the navigation at all. Usage is now everybody's own usage, and the platform's records are what "Records" has always been. Active state is decided server-side; dark/light stays Alpine (darkMode). Written as a comment tag rather than a hash-brace comment because that form is single-line only — spanning one over several lines makes Django render the whole block as visible page text.{% endcomment %}
